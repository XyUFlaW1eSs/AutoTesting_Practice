# 第 8 课：框架、报告与持续集成

## 目标
把零散脚本整理成可维护项目，使用日志、报告、Git 和 CI 自动运行。

## 推荐结构
```text
insurance-qa/
  tests/api/
  tests/ui/
  tests/unit/
  tests/conftest.py
  src/clients/
  src/pages/
  data/
  reports/
  requirements.txt
  pytest.ini
  README.md
```
按项目规模调整，避免为了目录而抽象。

## 报告
```powershell
python -m pytest -v --junitxml=reports/junit.xml
```
日志记录关键步骤、业务 ID、响应状态与耗时。敏感字段要脱敏；报告应包含测试名、输入数据、异常信息和定位线索。报告目录一般加入 .gitignore。

## 配置与秘密
base URL、超时和环境选择放入环境变量/配置；凭证使用本地环境变量或 GitHub Actions Secrets，不提交密钥、Token、密码和真实数据。

## CI 策略
PR 时运行快速、稳定测试；夜间/部署后运行更完整的回归和 UI 测试。失败后区分产品缺陷、环境、测试数据和脚本问题。不要通过无条件重试掩盖不稳定用例。

## 练习
增加 pytest.ini 和 JUnit 报告；将 API/UI 用例分组；创建 Git 分支并提交；配置 CI；分别分析一次成功和失败的流水线。

## 验收标准
新环境可按 README 安装运行；失败能定位；CI 自动执行测试且不泄露秘密。
