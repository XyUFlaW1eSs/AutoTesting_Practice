# 完整课程地图与阶段验收

目标：从初级软件/Web/数据库测试经验成长为能独立完成需求分析、测试设计、缺陷管理、UAT、接口自动化、UI 自动化及 CI 质量门禁的测试工程师。

## 学习原则
1. 每个知识点完成：理解概念、阅读示例、自己敲一遍、修改输入验证边界、记录失败原因。
2. 自动化不是替代测试设计。先明确风险、预期结果和测试数据，再决定是否自动化。
3. 测试必须可重复：固定数据、明确环境、隔离副作用、可读断言、失败证据完整。
4. 优先测试业务规则和接口；UI 自动化覆盖关键用户路径，不把所有检查放到浏览器层。
5. 练习只使用虚构保险业务和授权的本地测试环境。

## 完整路线与阶段交付

| 阶段 | 课程范围 | 必须交付 | 验收标准 |
|---|---|---|---|
| 0 工具 | 命令行、IDE、Git、虚拟环境、Markdown | 可复现的本地环境 | 能创建分支、提交、看差异、运行命令 |
| 1 测试基础 | 测试原则、生命周期、层级、风险、静态评审 | 测试策略与测试计划 | 能说明范围、风险、退出条件 |
| 2 测试设计 | 等价类、边界值、决策表、状态迁移、场景、探索式测试 | 需求追踪矩阵、用例集 | 关键需求具备正向、反向、边界、状态覆盖 |
| 3 缺陷与交付 | 缺陷生命周期、严重程度/优先级、证据、复测、回归、总结、UAT | 完整缺陷报告包、测试总结、UAT 报告 | 他人可复现，业务方可据报告决策 |
| 4 Web/HTTP/SQL | Network、HTTP、Cookie/Token、REST、SQL、数据一致性 | API 检查清单、SQL 校验脚本 | 能从 UI/API/DB 三层定位问题 |
| 5 Python 基础 | 类型、流程控制、函数、容器、模块、异常、文件、类 | 规则模块与练习 | 能独立编写结构清晰的 Python 程序 |
| 6 Python 工程 | venv、pip、JSON/CSV、日期、Decimal、日志、调试 | 数据驱动测试工具 | 处理异常数据、金额精度和文件编码正确 |
| 7 pytest | 断言、参数化、fixture、作用域、清理、标记、配置、mock、报告 | 可维护测试套件 | 测试独立运行、失败可诊断 |
| 8 API 自动化 | requests、状态码、响应结构、鉴权、超时、重试、幂等、链路 | API client 与业务流程测试 | 覆盖成功、错误、权限和数据副作用 |
| 9 数据库集成 | SQL、事务、测试数据准备/清理、API+DB 校验 | 集成测试层 | 能验证状态变化和数据不变量 |
| 10 Selenium | WebDriver、定位、等待、弹窗、iframe、Page Object | 关键路径 UI 测试 | 不依赖固定 sleep，失败有证据 |
| 11 Playwright | Locator、自动等待、断言、Context、网络、trace | UI 测试与诊断产物 | 定位稳定、状态隔离 |
| 12 框架工程化 | 配置、分层、日志、报告、并行、重试治理 | 可维护自动化框架 | 可读、可诊断、可复跑 |
| 13 Git/CI/CD | 分支、PR、Review、Actions、Secrets、制品 | CI 工作流 | PR 自动运行测试并保存报告 |
| 14 综合实战 | 投保、核保、支付、保单查询、权限与异常 | 作品集项目 | 可演示、可复跑、可解释剩余风险 |

## 推荐节奏
- 每周 5 天，每天约 2 小时；每周安排半天复盘。
- 先完成测试设计、缺陷与 UAT，再进入自动化。
- 每课采用：概念 30 分钟、跟练 45 分钟、独立练习 30 分钟、复盘 15 分钟。
- 每周把产物提交到 Git 分支，并记录做了什么、遇到什么问题、如何验证。

## 每阶段证据清单
### 手工测试与项目交付
- 需求拆解表、风险清单、需求—用例追踪矩阵。
- 至少 30 条测试用例，覆盖边界、异常、权限、状态和数据一致性。
- 3–5 份完整缺陷报告，包含环境、步骤、预期/实际、证据、影响、严重程度、优先级、复测记录。
- 缺陷日报、回归范围、测试总结、UAT 验收记录。

### 自动化工程
- Python 规则函数及单元测试。
- pytest 参数化、fixture、标记、mock 和报告。
- requests API 测试：成功、校验失败、未授权、资源不存在、重复提交、服务错误。
- SQL 数据核对脚本及测试数据准备/清理方案。
- Selenium 与 Playwright 关键路径测试。
- GitHub Actions CI：测试失败返回非零状态，报告上传为 artifact。

## 完成标准
不要以看完文档作为完成标准。每个模块都应能独立写出最小示例、解释每条断言、构造失败输入、判断测试层级、从 CI 证据定位问题，并说明尚未覆盖的风险。
