# 学习计划总览：手工测试 + 自动化测试

> 本文件是首轮六周执行计划；完整知识点与阶段验收见 [完整课程地图与阶段验收](完整课程地图与阶段验收.md)。各阶段应结合手工测试和自动化测试目录中的逐课示例完成。

## 目标岗位映射
JD 明确提到功能测试、手工测试、自动化、UAT 全流程验收测试。优先级：P0 手工功能测试与 UAT；P1 SQL/接口与 pytest 自动化；P2 Selenium、Playwright、Git/CI；保险业务与英语为加分准备。目标公司的实际技术栈需面试确认。

## 六周首轮安排（每天 2–3 小时）

| 周 | 主题 | 重点产出 |
|---|---|---|
| 1 | 测试流程、需求分析、用例、缺陷、Web | 30 条用例、完整缺陷报告、执行日报 |
| 2 | HTTP、API、SQL、回归与风险 | API 检查清单、SQL 校验、回归范围 |
| 3 | 保险业务、UAT 全流程 | UAT 计划、10–15 个业务场景、验收报告 |
| 4 | Python、pytest、fixture | 规则模块、参数化测试、fixture 与报告 |
| 5 | requests、数据库、Selenium、Playwright | API 链路、SQL 检查、关键 UI 路径 |
| 6 | 框架、日志/报告、Git、CI/CD | 可运行测试项目、PR 工作流、CI 报告 |

## 每日学习节奏
1. 概念学习 20–30 分钟。
2. 跟做示例 45–60 分钟。
3. 独立练习 45–60 分钟。
4. 复盘 15 分钟：记录错误、原因、解决方法和下一次复习日期。

## 执行规则
- 每周至少完成一个可评审交付物并提交 Git。
- 每个缺陷报告必须包含可复现步骤、预期/实际、环境、证据、影响与复测结果。
- 自动化用例必须有明确断言，不以“脚本运行结束”作为通过标准。
- 先保证核心规则与 API 覆盖，再增加 UI 自动化；不要为了课程数量重复维护低价值脚本。
- 六周是第一轮学习计划，不意味着已覆盖全部工作能力。完成后应以课程地图中的阶段验收和保险综合实战做查漏补缺。
