# 综合实战：模拟保险投保与保单管理验收项目

## 定位
虚构学习项目，用于练习功能测试、UAT、SQL、接口自动化、Selenium/Playwright 和 CI/CD。规则仅供教学，不代表真实保险产品，不能冒充真实企业经历。

## 业务链路
投保资料填写 → 服务端校验 → 提交申请 → 核保通过/拒绝 → 模拟支付 → 生成保单 → 查询保单。支付不连接真实支付服务。

## 练习规则
- 投保年龄 18–60 周岁（包含边界）。
- 保费必须大于 0，金额保留两位小数。
- 只有核保通过的申请可进入支付。
- 支付失败不得生成生效保单。
- 重复支付不得生成重复有效保单。
- 用户只能查询有权限访问的保单。
- 页面、接口和数据状态应一致。
规则有歧义时先记录待澄清问题。

## 阶段 A：手工测试与 UAT
- [ ] 测试计划、范围、风险、准入准出标准
- [ ] 30–50 条功能用例，覆盖边界、异常、权限、状态和重复提交
- [ ] 10–15 条端到端 UAT 场景
- [ ] 缺陷单、复测与回归记录
- [ ] UAT 执行记录、遗留风险和验收报告

## 阶段 B：接口与 SQL
- [ ] 手工验证申请、核保、支付、保单查询接口
- [ ] SQL 检查重复保单、金额不一致、状态不一致和孤儿记录
- [ ] 记录接口响应、业务 ID 与数据库证据

## 阶段 C：自动化
- [ ] Python 单元测试验证年龄/金额规则
- [ ] pytest 参数化覆盖边界和异常
- [ ] requests 校验 API 契约、业务状态和关联流程
- [ ] Selenium 基础 UI 回归路径
- [ ] Playwright 登录、投保、结果查询流程
- [ ] fixture、配置、测试数据、日志和报告

## 阶段 D：Git 与 CI
- [ ] feature 分支和清晰提交
- [ ] GitHub Actions 自动运行测试
- [ ] 保存 JUnit 报告，分析失败日志
- [ ] 记录一次失败、定位、修复与回归
