# 第 3 课：缺陷管理与回归测试

## 目标
写出可复现缺陷，评估影响，选择复测与回归范围。

## 缺陷单字段
标题、版本/环境、前置条件、测试数据、复现步骤、预期结果、实际结果、复现频率、截图/日志/请求响应、严重程度、优先级、需求关联。证据要脱敏。

## 示例
标题：同一投保申请重复支付生成两份保单（模拟缺陷）
- 前置：申请已核保通过。
- 步骤：连续两次提交同一申请的支付请求；查询支付记录和保单。
- 预期：同一申请仅产生一份有效支付结果与保单，重复请求按接口约定返回幂等结果。
- 实际：生成两份有效保单。
- 证据：申请 ID、请求时间、响应摘要和记录数量。
- 严重程度/优先级：按团队规范评估；涉及重复保单通常需要高优先级处理。

## 严重程度与优先级
严重程度描述对业务、数据、功能或用户的影响；优先级描述修复紧急度，受发布时间、影响范围和业务时机影响。二者相关但不完全相同。

## 缺陷流程
新建 → 待确认 → 已分配/修复中 → 待验证 → 关闭；复测失败则重新打开。实际状态依团队工具而异。

## 复测与回归
复测确认某缺陷是否修复；回归确认变更没有破坏相关既有功能。回归范围参考变更影响、调用链、共享组件、历史缺陷和业务风险。

## 练习
1. 为金额错误、越权查询、文案错字写缺陷单。
2. 为重复支付缺陷设计复测与 5 条回归用例。
3. 模拟开发无法复现，列出需要补充的证据。

## 验收标准
缺陷可复现；预期/实际清楚；能解释复测与回归差异和等级依据。
