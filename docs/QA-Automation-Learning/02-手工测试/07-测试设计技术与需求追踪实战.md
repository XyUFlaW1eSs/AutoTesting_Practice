# 测试设计技术与需求追踪实战

参考：[ISTQB CTFL 官方大纲](https://istqb.org/wp-content/uploads/2024/11/ISTQB_CTFL_Syllabus_v4.0.1.pdf)。本课使用虚构投保业务。

## 1. 从需求提取可测试条件
需求示例：“投保人年龄需在 18 至 60 岁之间（含边界）；保费必须大于 0 且最多两位小数；仅核保通过的申请可支付。”
拆解为：年龄最小/最大/边界包含性；年龄格式和缺失；保费正负、零、精度、格式；申请状态与支付权限；页面提示与服务端校验；错误请求是否改变数据库状态。
需求不清楚时提出问题并记录决策，不要自行猜测后将猜测写成预期结果。

## 2. 等价类
将输入划分为行为预计相同的组，再从每组选择代表值。
- 年龄有效类：18–60；无效类：小于 18、大于 60、非整数、空值。
- 保费有效类：正数且两位小数以内；无效类：零、负数、非数字、超过精度、极大值。
练习：为职业类别、证件类型、保单状态分别划分等价类，并解释每个类为什么可能有相同行为。

## 3. 边界值分析
对闭区间 18–60，重点检查 17、18、19、59、60、61。对保费下限大于 0，检查负值、0、最小合法单位、略大于合法范围的值。若规则是小数位最多两位，检查 1.2、1.20、1.201。
练习：为年龄和保费分别写边界表，记录输入、预期、实际和证据。

## 4. 决策表
将条件组合成规则，适用于核保/支付等多条件逻辑。

| 申请状态 | 支付结果 | 用户有权限 | 预期 |
|---|---|---|---|
| 核保通过 | 成功 | 是 | 生成一份有效保单 |
| 核保通过 | 失败 | 是 | 不生成有效保单 |
| 待核保 | 不发起 | 是 | 拒绝支付请求 |
| 已拒保 | 不发起 | 是 | 拒绝支付请求 |
| 核保通过 | 成功 | 否 | 拒绝访问，不生成用户可见的保单 |
| 已支付 | 重复请求 | 是 | 不重复扣款、不重复生成保单 |

练习：为重复回调、超时未知、管理员角色增加规则。

## 5. 状态迁移
为申请定义状态机：草稿 → 已提交 → 待核保 → 已通过/已拒绝 → 待支付 → 已支付 → 保单有效。状态转换必须以已确认业务规则为准。
测试有效转换、非法跳转、重复事件、事件乱序、并发提交和失败恢复。练习：画出状态图，列出每条合法边和至少 3 条非法边。

## 6. 场景法与探索式测试
从用户目标构建端到端场景，例如“合法投保直到查询保单”；再考虑中断、返回、重复点击、刷新、登录过期、网络中断和多标签页。
探索式测试要记录任务、假设、操作路径、发现、证据和未覆盖风险，而不是无记录地随意点击。

## 8. 用例模板
- 用例 ID、标题、需求 ID、优先级、前置条件、测试数据。
- 步骤与每一步预期结果。
- 实际结果、执行状态、环境、证据、关联缺陷。
- 自动化候选与选择理由。

## 9. 质量检查
- 每条高风险需求至少有一条正向、一条反向和一条边界/状态测试。
- 测试数据可重复，预期结果明确且来自已确认需求。
- 预期不应只写“正常”“成功”，而应说明状态、响应、页面结果和数据副作用。
- 记录无法执行的用例与原因，不将阻塞误报为通过。
- 设计完成后做用例评审，检查重复、遗漏、不可执行和预期模糊。

## 练习与验收
为投保、核保、支付和保单查询设计 30 条用例，覆盖等价类、边界、决策表、状态迁移、权限和端到端场景；完成需求追踪矩阵，并解释每条高风险用例为何放在对应测试层。
