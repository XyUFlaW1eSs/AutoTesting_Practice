# 第 2 课：需求分析与用例设计

## 目标
把业务描述转成可执行、可追踪、覆盖风险的测试用例。

## 分析步骤
1. 找参与者、前置条件、输入、输出、业务规则和状态。
2. 区分已明确规则与待确认问题；不要自行猜测。
3. 提取正常、异常、边界、权限、重复操作、状态变化和数据一致性场景。
4. 建立需求—测试点—用例追踪关系。

## 设计方法
- 等价类：把预期行为相同的输入分组，选代表值。
- 边界值：测最小、最大及相邻值。
- 判定表：多个条件组合决定结果时使用。
- 状态迁移：验证允许与禁止的状态跳转。
- 场景法：按用户端到端业务路径组合操作。
- 错误推测：补充重复提交、网络中断、会话过期等风险。

## 示例：年龄规则
假设练习产品要求投保年龄 18–60 周岁（包含边界），这不是任何真实产品规则。
| 输入 | 预期 |
|---|---|
| 17 | 拒绝并提示年龄不符合规则 |
| 18 / 30 / 60 | 年龄校验通过 |
| 61 | 拒绝 |
| 空值、字母、负数 | 按约定校验规则拒绝 |

## 用例模板
| 字段 | 示例 |
|---|---|
| 编号 | POL-AGE-001 |
| 标题 | 年龄等于最小允许值时可继续投保 |
| 前置条件 | 用户已登录，产品可投保 |
| 数据 | age=18 |
| 步骤 | 打开表单，输入年龄，提交 |
| 预期 | 校验通过；服务端按相同规则接受请求 |
| 优先级/需求关联 | P1 / REQ-POL-AGE |

## 质量检查
预期结果可验证；数据明确；步骤可重复；每条用例聚焦主要验证点；覆盖正常、异常、边界、权限和状态；尽量不依赖其他用例执行顺序。

## 练习
1. 为保费设计等价类和边界值。
2. 为“核保通过才能支付”设计状态迁移用例。
3. 写 10 条投保申请用例，含至少 3 条异常和 2 条权限/状态场景。

## 验收标准
其他测试人员能仅凭用例执行；能解释选择某种设计方法的理由。
