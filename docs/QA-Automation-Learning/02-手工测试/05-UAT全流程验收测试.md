# 第 5 课：UAT 全流程验收测试

## 目标
能制定验收计划、设计业务场景、准备数据、管理问题并输出验收结论。

## UAT 与功能测试
功能测试关注功能是否符合规格；UAT 关注业务用户能否完成真实业务目标。业务方/授权代表通常负责最终业务验收决定，测试人员提供执行证据与风险建议。

## 全流程
1. 确认目标、范围、角色、依赖与排除项。
2. 把“正常可用”转成可观察的验收标准。
3. 设计主流程、替代流程、异常、权限、金额和状态场景。
4. 准备环境、账号、产品配置、测试数据和清理方案。
5. 执行并记录步骤、结果、证据和状态。
6. 区分缺陷、需求变更、数据/环境问题、操作问题。
7. 跟踪修复、复测和关联回归。
8. 输出结果、遗留风险、限制与建议。
9. 由授权业务负责人按约定标准作出验收决定。

## 保险业务 UAT 场景示例
| 场景 | 验收预期 |
|---|---|
| 正常投保 | 申请、核保、模拟支付、保单状态连贯 |
| 年龄 17 岁 | 拒绝并提示 |
| 核保拒绝 | 不允许支付、不生成生效保单 |
| 支付失败 | 保单不得生效 |
| 重复支付 | 不生成重复有效保单 |
| 越权查询 | 不泄露他人保单 |
| 正常完成链路 | 页面、接口、记录状态一致 |

## 验收报告模板
项目/版本/日期；范围与排除项；环境与数据；场景总数及通过/失败/阻塞/未执行数量；关键缺陷；遗留风险；限制与建议；验收结论及决策人。

## 面试情境
- 通过率 95% 是否验收？不能只看比例，要看核心业务、失败场景、缺陷影响、约定标准和授权决策。
- 业务方认为缺陷不影响验收？记录证据与影响，按流程评估接受风险或书面豁免。
- 需求不明确？登记问题、负责人和决策时间，不擅自假设。

## 练习
完成 10–15 条 UAT 场景、执行记录和一份验收总结。

## 验收标准
能从计划走到结论；场景围绕业务目标；风险透明；不越权替业务负责人签署。
