# 需求规格说明书（教学项目）

## 1. 范围
实现投保申请、核保、模拟支付、保单签发和查询，覆盖常见测试工程实践。所有业务和数据均为虚构。

## 2. 角色与限制
- 投保操作员：创建申请、查看申请状态。
- 核保人员：批准或拒绝待核保申请。
- 支付服务（模拟）：处理已核保通过的申请。
- 保单服务：在模拟支付成功后生成保单。
当前 UI 仅演示工作台，没有完成正式身份认证与角色授权，不得将其视为生产可用。

## 3. 业务规则
- BR-01：年龄必须为 18–60 岁，包含边界。
- BR-02：投保人名称必填，长度不超过 100。
- BR-03：产品代码必填。
- BR-04：保费必须大于 0，最多两位小数。
- BR-05：新申请状态为 Pending。
- BR-06：仅 Pending 可核保一次，核保后状态为 Approved 或 Rejected。
- BR-07：只有 Approved 可模拟支付。
- BR-08：支付成功后申请变为 Paid，创建一条成功支付记录与一份 Active 保单。
- BR-09：同一申请不得创建多份保单；支付接口应处理重复请求。
- BR-10：不存在的申请/保单返回 404；非法状态转换返回 409。
- BR-11：UI、API 与数据库的业务状态应一致。

## 4. 非功能要求
- API 提供 health endpoint 与开发环境 Swagger。
- 关键写操作应由数据库约束与事务保护业务不变量。
- 测试数据全部虚构，脚本不删除已有数据库数据。
- 正式上线前必须补齐认证授权、审计、HTTPS、安全配置、备份与监控。

## 5. 验收标准
1. 合法申请创建返回 201。
2. 年龄越界、空姓名、无效保费返回 400，且没有对应新增记录。
3. Pending 或 Rejected 申请支付返回 409，不产生支付/保单。
4. Approved 申请支付成功，申请状态 Paid，生成一条成功支付和一份有效保单。
5. 同一申请重复支付，不产生重复保单。
6. 重复核保返回 409。
7. 不存在的资源返回 404。
8. pytest API 回归可以重复执行，报告包含失败用例和断言。
9. Vue 页面能创建申请、核保、模拟支付并显示保单。
10. 构建脚本能生成后端发布目录和前端静态产物。
