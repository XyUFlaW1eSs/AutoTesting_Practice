# 测试策略与风险矩阵

## 测试层级
- 单元测试：年龄、保费、状态转换等纯规则。
- API 集成测试：状态码、响应结构、业务流程和副作用。
- 数据库验证：约束、关联、金额、重复数据与事务。
- UI 测试：关键用户旅程和用户可见反馈。
- 手工探索：异常中断、可用性、权限和需求不清晰处。

## 风险矩阵
| 风险 | 影响 | 优先级 | 测试策略 |
|---|---|---|---|
| 年龄/保费校验绕过 | 不合规申请 | P1 | 等价类、边界、API 负向 |
| 未核保先支付 | 违规状态/错误签发 | P0 | 状态迁移、API、DB |
| 重复支付/重复保单 | 财务与业务数据错误 | P0 | 幂等、并发、唯一约束 |
| 支付失败却签发 | 错误保单 | P0 | 故障注入与 DB 断言 |
| 核保重复提交 | 状态覆盖 | P1 | 并发/重复请求 |
| UI 与 DB 不一致 | 用户误判 | P1 | 端到端与 SQL |
| 认证/对象授权缺失 | 数据泄露 | P0 | 当前版本明确为已知限制，作为后续安全扩展验收项 |

## 测试数据
使用随机后缀生成投保人和幂等键；禁止在共享环境使用真实个人数据。每条用例独立创建数据，不依赖数据库 ID 固定值。API 集成测试只能连接专门的测试数据库。

## 进入条件
- 需求规则已确认；测试环境可用；数据库初始化完成；API health 返回 200。
## 退出条件
- P0 用例全部通过；无未评估的阻断缺陷；测试报告记录覆盖盲区、失败原因和风险接受人。
