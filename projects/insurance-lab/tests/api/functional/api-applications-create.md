# POST /api/applications — API 测试用例

## 接口契约基线

请求字段：applicantName、age、productCode、premium。
当前实现规则：姓名 Trim 后必填且长度不超过 100；年龄 18–60（含边界）；产品代码 Trim 后必填并转大写；保费必须大于 0 且最多两位小数。成功返回 201 和新建申请信息，初始状态 Pending。

重要限制：当前 Handler 未显式限制 productCode 的 30 字符数据库长度、premium 的 NUMERIC(12,2) 上限，也未显式做业务级类型校验；这类用例需验证是否产生非预期 500，并作为实现风险处理。

## 用例

### FT-APPCREATE-001 — 完整合法申请创建成功

- 优先级：P0
- 类型：功能 / 冒烟
- 前置条件：API 和专用测试数据库可用。
- 数据：applicantName=QA-唯一值，age=30，productCode=LIFE-BASIC，premium=1250.00。
- 步骤：
  1. POST /api/applications，提交完整 JSON。
  2. 检查状态码和响应体。
  3. GET /api/applications，按返回 id 检查记录。
- 预期结果：
  1. HTTP 201。
  2. 响应包含 id、applicantName、age、productCode、premium、status。
  3. id 为正整数，status=Pending。
  4. 姓名去除首尾空格，产品代码转换为大写。
  5. 列表中能查到同一申请，且字段一致。
- 状态：现状可验证。
